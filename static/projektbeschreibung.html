Projektbeschreibung
März 2026

1. Projektziel

🎯 Kidstorte ist ein KI-gesteuerter Chatbot für eine Konditorei. Kunden können auf der Website ihre Traumtorte per Chat beschreiben, ein KI-generiertes Bild davon sehen und am Ende eine Bestellung mit Kontaktdaten aufgeben — vollständig automatisiert.

Der Chatbot stellt gezielte Fragen (Anlass, Geschmack, Gäste, Dekoration usw.), versteht die Antworten mithilfe von KI, erstellt ein Bild der gewünschten Torte und schickt die fertige Bestellung per E-Mail an den Designer und den Kunden. Im passwortgeschützten Admin-Panel kann der Betreiber alle Bestellungen verwalten und die Bot-Texte live anpassen.

3. Projektstruktur – Jede Datei erklärt

Backend (Python / Server)

Datei Rolle Was macht sie?
main.py Der Kellner Empfängt alle Anfragen vom Browser, leitet sie weiter und gibt Antworten zurück. Enthält alle API-Endpunkte (/api/chat, /api/submit-order, /admin).
graph.py Der Dirigent Steuert den Gesprächsablauf mit LangGraph. Entscheidet: Welcher Schritt kommt als nächstes? (Frage stellen → Bild erzeugen → Bestellen)
nodes.py Die Arbeiter Führt die eigentliche KI-Arbeit aus: Intent klassifizieren, Bestelldaten sammeln, Bild mit DALL-E generieren, Bestellung finalisieren.
state.py Das Gedächtnis Definiert den AgentState: Was weiß der Bot aktuell? (intent, order_info, messages, image_url, order_complete…)
session_manager.py Der Aktenschrank Speichert jede Kundensitzung getrennt in ChromaDB. Ermöglicht Multi-User-Betrieb: Jeder Kunde hat seinen eigenen Gesprächsverlauf.
order_db.py Das Bestellbuch Speichert abgeschlossene Bestellungen dauerhaft in SQLite. Funktionen: save_order(), get_all_orders(), update_order_status().
email_service.py Der Briefträger Sendet HTML-E-Mails via SMTP an Designer (neue Bestellung) und Kunden (Bestätigung). Fällt sicher aus, wenn SMTP nicht konfiguriert ist.
config.py Die Einstellungen Lädt alle geheimen Variablen aus der .env-Datei (API-Keys, SMTP-Passwort, Admin-Passwort) und stellt Funktionen zum Laden/Speichern der YAML-Config bereit.
monitoring.py Die Statistiken Zählt Anfragen, Fehler, Antwortzeiten und Token-Verbrauch im Hintergrund. Erreichbar unter /metrics.

Frontend (Browser / HTML)

Datei Rolle Was macht sie?
templates/index.html Die Kunden-Website Das Chatfenster für Kunden. Zeigt Nachrichten, KI-Tortenbild und das Adressformular bei Bestellabschluss.
templates/admin.html Das Admin-Panel Passwortgeschütztes Dashboard: Bestellungen verwalten, Bot-Texte live bearbeiten, aktive Sitzungen anzeigen.
static/script.js Die Logik im Browser Sendet Nachrichten per Fetch-API, zeigt Antworten an, steuert Adressformular und Reset-Button.
static/style.css Das Design Alle visuellen Stile: Chat-Blasen, Adressformular, Admin-Tabellen, Animationen.

Konfiguration

Datei Inhalt
prompts_config.yaml Alle Bot-Texte und System-Prompts. Können im Admin-Panel live geändert werden, ohne Server-Neustart.
.env Geheime Schlüssel: OpenAI API-Key, SMTP-Zugangsdaten, Admin-Passwort. Wird nie ins Git eingecheckt.
kidstorte.db SQLite-Datenbankdatei mit allen abgeschlossenen Bestellungen (automatisch erstellt).

4. Verwendete Technologien

⚡
FastAPI
Python Web-Framework. Verarbeitet HTTP-Anfragen vom Browser schnell und asynchron.
🔗
LangGraph
Steuert den Gesprächsablauf als Graph. Jeder Knoten (Node) ist ein Schritt im Gespräch.
🧠
OpenAI GPT-4.1-mini
Beantwortet Kundenfragen, klassifiziert Absichten und sammelt Bestelldaten.
🖼️
OpenAI DALL-E
Generiert ein realistisches Bild der bestellten Torte auf Basis der Kundenbeschreibung.
🗄️
ChromaDB
Vektordatenbank für Sitzungen (Multi-User) und RAG-Wissensabruf.
💾
SQLite
Relationale Datenbank für dauerhafte Bestellspeicherung inkl. Kundendaten und Status.
📧
SMTP / GMX
Automatischer E-Mail-Versand an Designer und Kunden nach Bestellabschluss.
🐍
Python + Pydantic
Gesamte Serverlogik in Python. Pydantic validiert Datenstrukturen (State, Requests).

5. Eingesetzte KI-Konzepte

  • LangGraph
    Stateful Agent als Graph: Der Gesprächsfluss wird als gerichteter Graph modelliert. Jeder Knoten ist eine Funktion (z.B. collect_order_info). Der Graph entscheidet anhand des Zustands, welcher Knoten als nächstes ausgeführt wird.
  • RAG
    Retrieval Augmented Generation: Der Bot kann auf Wissen aus gespeicherten Dokumenten (z.B. Tortenkatalog) zugreifen, das in ChromaDB als Vektoren gespeichert ist, und dieses in seine Antworten einfließen lassen.
  • Intent
    Intent-Klassifikation: Bei jeder Nachricht erkennt der Bot die Absicht des Kunden (bestellen, fragen, Bild wünschen, bestätigen, abbrechen) und wählt die passende Aktion.
  • Multi-User
    Session-Management: Jeder Kunde bekommt eine eindeutige Session-ID per Cookie. Der Agent-Zustand wird pro Sitzung in ChromaDB gespeichert, sodass mehrere Kunden gleichzeitig chatten können.
  • DALL-E
    Text-to-Image: Aus den gesammelten Tortenmerkmalen wird ein beschreibender Prompt gebaut, der an DALL-E 3 gesendet wird, um ein realistisches Tortenbild zu generieren.
  • Hot-Reload
    Live-Konfiguration: Die System-Prompts werden aus einer YAML-Datei geladen und bei jedem Request neu eingelesen — Änderungen wirken sofort ohne Server-Neustart.

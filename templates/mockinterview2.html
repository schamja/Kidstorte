Kidstorte — Projekt-spezifische Fragen

Fragen über Architektur, Implementierung und Entscheidungen in deinem Projekt

1 RAG im Projekt
FWas ist RAG und warum verwenden Sie es in Ihrem Projekt?▾

RAG steht für Retrieval Augmented Generation. Statt das LLM alle Informationen "auswendig" wissen zu lassen, holen wir relevante Dokumente aus einer Wissensdatenbank und geben sie dem LLM als Kontext mit.

In Kidstorte nutzen wir RAG für Preisberechnungen und Produktinfo-Fragen. Die Preise, Allergieinfos und Produktbeschreibungen liegen als Chunks in einer ChromaDB-Collection namens cake_chunks. Bei einer Preisfrage wird die Bestellung als Query embeddet, die Top-5-relevantesten Chunks geholt und dem LLM mitgegeben — statt zu halluzinieren.

FWelches Embedding-Modell nutzen Sie und warum?▾

text-embedding-3-small von OpenAI. Es kostet nur ~$0.02 pro 1 Million Tokens und reicht für unseren deutschen Tortenkontext völlig aus. Wir brauchen keine semantische Suche über riesige Korpora, sondern matchen Bestelldetails gegen Produktdaten.

FWann wird RAG ausgelöst und wann nicht?▾

RAG wird nur bei price- und info-Intents ausgelöst — also wenn der Kunde nach Preisen oder allgemeinen Infos fragt. Bei normalen Bestellschritten (order, change, greeting) wird kein RAG gemacht.

Das spart Kosten, weil Embedding-Calls und DB-Queries nur stattfinden, wenn wir tatsächlich Produktwissen brauchen.

FChromaDB — warum nicht Pinecone oder FAISS?▾

ChromaDB ist Open Source, lokal, serverless und braucht keinen externen Service. Für ein Einzelprojekt mit ~100-200 Dokumenten ist es perfekt.

  • Pinecone: Overkill — Cloud-hosted, kostenpflichtig, Vendor Lock-in
  • FAISS: Kein Persistence-Layer built-in
  • ChromaDB: Embeddings + Persistence + Metadaten in einer Library
2 LangGraph / State Machine
FVerwenden Sie LangGraph als Library?▾

Nein, wir haben einen eigenen LangGraph-ähnlichen Graphen implementiert. In graph.py gibt es eine run()-Methode, die den State durch verschiedene Nodes routet, je nach erkanntem Intent.

Das Prinzip ist identisch zu LangGraph: stateless Nodes, die einen AgentState-Dict empfangen, verarbeiten und zurückgeben. Vorteil: volle Kontrolle, keine Library-Abhängigkeit, jede Zeile verständlich.

FWie sieht der Graph-Flow aus?▾
User Input → Guardrail → classify_and_extract → ROUTING: ├─ greeting → greet() ├─ order → check_complete() → ask_next() ODER summarize_order() → generate_image() ├─ price → retrieve_docs() → calculate_price() ├─ image → generate_image() ├─ info → retrieve_docs() → answer_question() ├─ change → update_order() ├─ finalize → finalize_order() → show_address_form └─ offtopic → redirect()
FWas ist der AgentState?▾

Ein TypedDict mit allen Feldern, die durch den Graphen fließen:

  • user_input, messages (Chatverlauf), intent
  • order_info — Dict mit 13 Feldern (anlass, geschmack, form, schichten, ...)
  • missing_fields, order_complete, question_todo
  • context (RAG), image_url, calendar_available

Jeder Node liest und schreibt auf diesem State.

FWas ist das question_todo-System?▾

Unser Fortschrittstracker. Für jedes Pflichtfeld gibt es einen Status:

pending → asked → answered

So vermeiden wir, dass der Bot zweimal nach der gleichen Info fragt. Der ask_next-Node wählt immer ein Feld mit Status pending oder asked.

FWarum stateless Nodes?▾

Stateless Nodes sind einfach zu testen, debuggen und replizieren. Der gesamte State wird zwischen Requests in ChromaDB persistiert. Man kann einen fehlerhaften Durchlauf reproduzieren, indem man den State kopiert und den Node erneut aufruft. Außerdem ermöglicht es theoretisch horizontale Skalierung.

3 LLM-Strategie
FWelches Modell nutzen Sie und warum?▾

gpt-4o-mini für alle Aufgaben. Es ist 33x günstiger als gpt-4o ($0.15 vs $5 pro 1M Input-Tokens) und reicht für unseren Anwendungsfall völlig aus. Pro Request zahlen wir ca. $0.0003 USD.

FWie viele LLM-Calls pro Bestellschritt?▾

Typisch 2 Calls pro Nachricht:

  1. classify_and_extract — Intent + Datenextraktion in einem Call
  2. ask_next — Nächste Frage generieren

Ursprünglich waren Intent-Klassifikation und Extraktion getrennt (2 Calls). Durch die Kombination sparen wir 50% der LLM-Kosten pro Nachricht.

FWie steuern Sie die Temperature?▾
TemperatureEinsatzGrund
0Klassifikation, Extraktion, PreisDeterministisch, kein Halluzinieren
0.3InformationsantwortenLeichte Variation
0.6ask_next (Fragengenerierung)Natürlich, freundlich, abwechslungsreich
FWie handhaben Sie Retry-Logik bei API-Fehlern?▾

@retry_on_transient(max_retries=3, base_delay=5.0) mit exponentiellem Backoff: 5s → 10s → 20s. Das fängt Rate-Limits und transiente Fehler ab, ohne die API zu überfluten.

4 Prompt Engineering
FWo werden Ihre Prompts verwaltet?▾

In prompts_config.yaml — einer YAML-Datei, die hot-reloadable ist. Der Admin kann Prompts live bearbeiten, ohne den Server neu zu starten. Bei jedem Zugriff wird die Datei-Änderungszeit geprüft und bei Bedarf neu geladen.

FWie verhindern Sie Halluzinationen?▾
  • Explizite Verbote: "ERFINDE NIEMALS Werte die der Kunde nicht gesagt hat"
  • RAG-Kontext für Preise — LLM berechnet nur aus gegebenen Daten
  • Strukturierte JSON-Ausgabe — nur erwartete Felder
  • JSON-Repair: parse_llm_json() sendet bei Parse-Fehlern den Output zurück ans LLM zur Selbstkorrektur
FWie behandeln Sie Tippfehler?▾

Im Prompt steht explizit: "Schokolde → Schokolade, Vanile → Vanille". Das LLM korrigiert Tippfehler automatisch. Bei Namen (z.B. "Aron") wird aber nicht korrigiert — die bleiben wie eingegeben.

FWas passiert bei mehrdeutigen Eingaben wie "ja" oder "3"?▾

Der Prompt definiert kontextabhängige Regeln:

  • "ja" → Kontext der letzten Bot-Frage entscheidet
  • "3" → wenn Bot nach Schichten fragte: {schichten: "3"}
  • Emojis → werden ignoriert
  • "Ronaldo", "Elsa" als Deko → Intent order (nicht offtopic!)
5 Session Management & Persistenz
FWie werden Sessions gespeichert?▾

In ChromaDB, Collection sessions. Pro Session wird der gesamte AgentState als JSON gespeichert mit Metadaten: created, last_accessed, message_count, has_order, order_complete.

Die Session-ID kommt aus einem HTTPOnly-Cookie (cake_session_id), gültig für 24 Stunden.

FWas passiert bei Session-Timeout?▾

cleanup_old_sessions() löscht Sessions, die länger als SESSION_TTL_HOURS (24h) nicht zugegriffen wurden. Der Chatverlauf ist auf max 20 Nachrichten begrenzt, um Context-Window-Overflow zu vermeiden.

6 Bildgenerierung
FWie generieren Sie Tortenvorschau-Bilder?▾

Eine Provider-Chain: Erst OpenAI gpt-image-1, bei Fehler Fallback auf HuggingFace FLUX.1-schnell oder SDXL. Der Bild-Prompt wird vom LLM generiert basierend auf den Bestelldaten (Form, Farbe, Geschmack, Dekoration, Schichten).

FWie lösen Sie das Moderationsproblem bei Personennamen?▾

Namen werden in figürliche Beschreibungen umgewandelt:

  • Ronaldo → "famous soccer player figurine made of fondant"
  • Elsa → "ice queen princess figurine"

Das Wort "figurine" signalisiert: keine echte Person, sondern eine Tortenfigur.

FGibt es ein Portfolio-System?▾

Ja! _find_best_reference() scannt den Bilder/-Ordner nach ähnlichen Torten per Dateinamen-Matching (kein LLM nötig!). Score: +2 für Figurname, +1 für Etagenzahl, +1 für Farbe. Ab Score ≥2 wird ein Referenzbild vorgeschlagen.

7 Kostenoptimierung
FWelche Strategien nutzen Sie zur Kostenoptimierung?▾

Fünf Strategien:

  1. Modellwahl: gpt-4o-mini für alles (~$0.0003 pro Request)
  2. Combined classify+extract: 1 statt 2 LLM-Calls pro Nachricht
  3. Response Cache: SHA256-basierter LRU-Cache (200 Einträge, 1h TTL)
  4. Selektives RAG: Nur bei price/info-Intent
  5. Message Truncation: Max 3000 Tokens Kontext
FWas kostet eine komplette Bestellung?▾

Ca. 8-12 Nachrichten × ~$0.0003 = unter $0.004 USD für eine vollständige Bestellung. Bildgenerierung zusätzlich ~$0.04 bei OpenAI.

8 LangSmith Monitoring
FWas tracen Sie mit LangSmith?▾

Drei Ebenen:

  1. Node-Level: @trace_node Decorator — Input, Output, Duration
  2. LLM-Level: trace_llm_call() — Prompt, Response, Modell, Dauer
  3. Graph-Level: Gesamter Flow von Input bis Response

Alles im Projekt "Kidstorte" auf smith.langchain.com sichtbar.

FWas passiert wenn LangSmith nicht erreichbar ist?▾

Graceful Degradation: if not is_enabled(): yield _DummyRun(). Der Bot funktioniert normal weiter, nur ohne Tracing. Kein Single Point of Failure.

9 Fehlerbehandlung & Sicherheit
FWas passiert bei einem LLM-Timeout?▾
  1. Retry: 3 Versuche mit exponentiellem Backoff (5s, 10s, 20s)
  2. @safe_node: Fängt alle Exceptions, gibt freundliche Fehlermeldung
  3. Guardrail: Blockt Spam (>800 Zeichen) bevor der LLM-Call stattfindet
FWie schützen Sie vor Prompt Injection?▾

Der guardrail()-Node ist der erste Node im Graphen. Er prüft per LLM-Call ob der Input ein Jailbreak-Versuch, Spam oder missbräuchlich ist. Wenn ja, wird guardrail_blocked = True gesetzt — der Rest des Graphen wird nicht durchlaufen.

10 Architektur-Entscheidungen
FWarum kein LangChain Framework?▾

LangChain bringt Overhead und Abstraktion. Unser Graph hat ~300 Zeilen, ist vollständig verständlich und debuggbar. Wir nutzen das Prinzip von LangGraph (stateless Nodes, conditional Routing), aber ohne die Library-Abhängigkeit.

FWarum FastAPI statt Flask?▾
  • Async nativ: Für LLM-Calls die 1-3s dauern
  • OpenAPI-Dokumentation: Automatisch generiert
  • Streaming (SSE): Für Wort-für-Wort-Antworten einfach umzusetzen
FWas sind die 5 Säulen Ihres Projekts?▾
  1. RAG — Wissensdatenbank für Preise und Produktinfos
  2. LangGraph — State-Machine für den Bestellfluss
  3. ChromaDB — Vektordatenbank für RAG + Sessionpersistenz
  4. Vision/Bildgenerierung — Tortenvorschau mit OpenAI/HuggingFace
  5. LangSmith — Monitoring, Tracing und Evaluation
FWie würden Sie das System skalieren?▾

Da Nodes stateless sind und State in ChromaDB liegt, könnten wir mehrere FastAPI-Worker starten (Uvicorn workers). ChromaDB müsste durch einen externen Service ersetzt werden (z.B. ChromaDB Server-Modus oder Pinecone). Der Cookie-basierte Session-Ansatz funktioniert auch mit Load Balancing.

FWas würden Sie verbessern?▾
  • Evaluations: Systematische Testdatensätze mit erwarteten Outputs
  • Multi-Agent: Spezialisierte Agenten für Preis, Bild, Beratung
  • Streaming überall: Aktuell nur für Chat, nicht für Bildgenerierung
  • Mehrsprachigkeit: Prompts parametrisieren für EN/TR/AR

Theoretische Fragen über LLMs, LangChain, LangGraph, LangSmith, RAG, Agenten

1 LLM — Grundlagen
FWas ist ein LLM und wie funktioniert es?▾

Ein Large Language Model ist ein neuronales Netz (Transformer-Architektur), das auf riesigen Textmengen trainiert wurde. Es lernt statistische Muster der Sprache und kann Text generieren, indem es Token für Token vorhersagt: "Was ist das wahrscheinlichste nächste Wort?"

FVergleich: GPT-4o vs. GPT-4o-mini vs. GPT-3.5▾
ModellStärkeKosten (Input/1M)Einsatz
GPT-3.5Schnell, günstig$0.50Einfache Tasks
GPT-4o-miniGute Qualität, sehr günstig$0.15Best Value — 90% der Aufgaben
GPT-4oBeste Qualität$5.00Komplexe Reasoning-Tasks
GPT-4.1Neuestes, best coding$2.00Coding, lange Kontexte
FWas ist ein Token?▾

Die kleinste Einheit, die ein LLM verarbeitet. "Schokoladentorte" wird z.B. in 3-4 Tokens zerlegt. Faustregel: 1 Token ≈ 4 Zeichen (Englisch) bzw. 1 Token ≈ 3 Zeichen (Deutsch). Tokens bestimmen den Preis und das Context Window.

FWas ist das Context Window?▾

Die maximale Anzahl Tokens, die ein LLM gleichzeitig "sehen" kann — Input + Output zusammen. GPT-4o-mini hat 128K Tokens. Wenn man es überschreitet, "vergisst" das Modell ältere Inhalte.

FWas ist Temperature?▾
  • Temperature 0: Deterministisch — immer die wahrscheinlichste Antwort
  • Temperature 0.3-0.7: Leichte Variation — natürlicher Text
  • Temperature >1: Sehr kreativ, aber unvorhersagbar
FWas sind Halluzinationen und wie vermeidet man sie?▾

Halluzinationen sind Fälle, in denen das LLM Fakten erfindet. Vermeidung:

  1. RAG — Fakten aus Datenbank liefern
  2. Strukturierte Outputs — JSON-Format erzwingen
  3. Explizite Prompts — "Antworte nur basierend auf dem Kontext"
  4. Temperature 0 für Fakten-Tasks
  5. Grounding — Quellen mitliefern

FSystem-Prompt, User-Prompt, Assistant-Prompt — Unterschied?▾
  • System-Prompt: Definiert Rolle und Regeln ("Du bist ein Tortenberater...")
  • User-Prompt: Die Eingabe des Nutzers
  • Assistant-Prompt: Vorherige Antworten des Bots (für Konversationskontext)

Das LLM bekommt alle drei als messages-Array und antwortet basierend auf dem Gesamtkontext.

2 RAG — Theorie
FErklären Sie RAG im Detail.▾

RAG besteht aus 3 Schritten:

  1. Indexing: Dokumente → Chunks → Embeddings → Vektordatenbank
  2. Retrieval: User-Frage → Embedding → Cosine Similarity → Top-K Chunks
  3. Generation: Chunks als Kontext + LLM → Antwort
User-Frage → Embedding → Vektorsuche → Top-K Chunks → LLM + Kontext → Antwort
FWas ist ein Embedding?▾

Eine Vektordarstellung (z.B. 1536 Dimensionen) von Text. Semantisch ähnliche Texte haben ähnliche Vektoren. "Schokoladentorte" und "Chocolate Cake" hätten Vektoren die nahe beieinander liegen — semantische Suche statt Keyword-Matching.

FWas ist Cosine Similarity?▾

Ein Maß für die Ähnlichkeit zweier Vektoren (Winkel zwischen ihnen):

  • 1.0 = identisch
  • 0.0 = keine Ähnlichkeit
  • -1.0 = gegensätzlich
FWas ist Chunking und warum ist es wichtig?▾

Chunking teilt große Dokumente in kleinere Stücke (z.B. 500 Tokens):

  • Präzision: Kleine Chunks sind gezielter als ganze Dokumente
  • Token-Limit: Context Windows sind begrenzt
  • Kosten: Weniger Kontext = günstiger

Strategien: Fixed-Size, Sentence-Based, Semantic Chunking, Recursive Character Splitting.

FNaive RAG vs. Advanced RAG?▾

3 LangChain
FWas ist LangChain?▾

Ein Framework für LLM-Anwendungen mit Abstraktionen für:

  • Models: Einheitliche Schnittstelle (OpenAI, Anthropic, Cohere, ...)
  • Prompts: Templates, Few-Shot, Output Parser
  • Chains: Verkettung mehrerer LLM-Calls
  • Memory: Konversationsgedächtnis
  • Tools/Agents: LLM kann externe APIs aufrufen
  • Retrievers: RAG-Integration
FWas ist eine Chain in LangChain?▾

Eine Pipeline die mehrere Schritte verbindet:

chain = prompt_template | llm | output_parser # Beispiel: chain = ( ChatPromptTemplate.from_template("Klassifiziere: {input}") | ChatOpenAI(model="gpt-4o-mini") | JsonOutputParser() ) result = chain.invoke({"input": "Ich will eine Torte"})
FWas ist LCEL (LangChain Expression Language)?▾

Die deklarative Syntax von LangChain v0.2+ für Chains:

chain = prompt | model | parser # Der "|" Operator

Vorteile: Streaming, Batch, Async, Parallelisierung "gratis".

Nachteil: Abstrakt, schwer zu debuggen, magisches Verhalten.

ConversationSummaryMemoryLLM fasst alte Nachrichten zusammen

4 LangGraph
FLangGraph vs. LangChain — Unterschied?▾
LangChain Chain: A → B → C → D (linear) LangGraph: A → B → [C oder D] → zurück zu B? (zyklisch)

LangGraph erlaubt Schleifen, Bedingungen und parallele Pfade — ideal für Agenten, die Entscheidungen treffen und Schritte wiederholen müssen.

FWas sind die Kernkonzepte von LangGraph?▾
  1. StateGraph: Der Graph selbst
  2. Nodes: Funktionen die den State transformieren
  3. Edges: Verbindungen zwischen Nodes
  4. Conditional Edges: Routing basierend auf State-Werten
  5. State: TypedDict/Pydantic-Modell das durch den Graphen fließt
  6. Checkpointer: Persistiert State zwischen Aufrufen
from langgraph.graph import StateGraph, END graph = StateGraph(AgentState) graph.add_node("classify", classify_node) graph.add_node("ask", ask_node) graph.add_conditional_edges("classify", route_by_intent, { "order": "ask", "complete": "summarize", "end": END }) graph.add_edge("ask", "classify") # Schleife!
FWas ist ein Checkpointer in LangGraph?▾

Speichert den Graph-State nach jedem Node-Durchlauf. Ermöglicht:

  • Pausieren und fortsetzen (auf User-Input warten)
  • Time-Travel: Zu früheren States zurückspringen
  • Multi-Turn-Conversations: State über Requests hinweg behalten

Verfügbar: MemorySaver, SqliteSaver, PostgresSaver.

FWas ist ein Multi-Agent-Graph?▾
Orchestrator-Agent ├─ Beratungs-Agent (Empfehlungen, Smalltalk) ├─ Preis-Agent (RAG + Kalkulation) ├─ Bild-Agent (Prompt-Engineering + Generierung) └─ Termin-Agent (Kalender-Integration)

Jeder Agent hat eigene Prompts, Tools und Expertise. Der Orchestrator routet die Anfrage an den passenden Spezialisten.

5 LangSmith
FWas ist LangSmith?▾

Die Observability-Plattform von LangChain für LLM-Anwendungen. Drei Säulen:

  1. Tracing: Jeder LLM-Call aufgezeichnet — Input, Output, Dauer, Kosten, Fehler
  2. Monitoring: Dashboards mit Metriken — Latenz, Fehlerrate, Token-Verbrauch
  3. Evaluations: Automatische Qualitätsbewertung der LLM-Outputs
FWas sind LangSmith Evaluations?▾

Testdatensätze mit erwarteten Outputs:

{"input": "Ich will eine Schokotorte", "expected_intent": "order"} {"input": "Was kostet das?", "expected_intent": "price"} {"input": "Hallo!", "expected_intent": "greeting"}

Evaluatoren: Exact Match, LLM-as-Judge, Custom-Metriken.

6 AI Agents
FWas ist ein AI Agent?▾

Ein LLM, das autonom Entscheidungen trifft und Aktionen ausführt:

  1. Planen: Aufgabe in Schritte zerlegen
  2. Tools nutzen: APIs aufrufen, Datenbanken abfragen
  3. Beobachten: Ergebnisse auswerten
  4. Iterieren: Nächsten Schritt basierend auf Ergebnissen wählen
Schleife: Think → Act → Observe → Think → Act → ...
FAgent vs. Chain — Unterschied?▾
  • Chain: Feste Abfolge A → B → C. Immer gleich.
  • Agent: Dynamische Abfolge. LLM entscheidet bei jedem Schritt. Kann Schleifen machen, Tools wählen, abbrechen.
FWas ist ReAct (Reasoning + Acting)?▾
Thought: Ich muss den Preis nachschlagen. Action: search_knowledge_base("Schokoladentorte Preis") Observation: Schokoladentorte M: 45€, L: 55€, XL: 65€ Thought: 10 Gäste = Größe L. Action: respond("Der Preis für Größe L beträgt 55€.")

Das LLM "denkt laut nach" (Reasoning), führt Aktionen aus (Acting) und nutzt die Ergebnisse für den nächsten Schritt.

FWas sind Tools in Agenten?▾

Funktionen, die das LLM aufrufen kann:

tools = [ {"name": "check_calendar", "desc": "Prüft Verfügbarkeit"}, {"name": "calculate_price", "desc": "Berechnet Tortenpreis"}, {"name": "search_products", "desc": "Sucht in Wissensdatenbank"}, {"name": "generate_image", "desc": "Erstellt Tortenbild"}, ]

Das LLM wählt basierend auf der Nutzeranfrage das passende Tool.

FWas ist Function Calling / Tool Use?▾

Modernes LLM-Feature: Das Modell gibt strukturiert einen Tool-Aufruf zurück:

// LLM Output: { "function_call": { "name": "check_calendar", "arguments": {"date": "2026-03-27"} } }

Der Code führt die Funktion aus und gibt das Ergebnis zurück ans LLM.

FSingle Agent vs. Multi-Agent — wann was?▾
Single Agent: LLM → [Tool1, ..., Tool15] ← wird unzuverlässig Multi-Agent: Orchestrator-LLM ├─ Agent A → [Tool1, Tool2] ├─ Agent B → [Tool3, Tool4] └─ Agent C → [Tool5, Tool6]

Single: Einfach, aber >10 Tools problematisch.
Multi: Jeder Agent hat nur 2-3 Tools, zuverlässiger.

FWas ist Human-in-the-Loop?▾

Der Agent pausiert und wartet auf menschliche Bestätigung:

  • Vor Bestellung: "Soll ich abschicken?"
  • Bei Unsicherheit: "Meinen Sie X oder Y?"
  • Bei kritischen Aktionen: "Termin am 27.03. buchen?"

In Kidstorte: Das Adressformular und die Bestätigungsvorschau sind Human-in-the-Loop.

  • Text → Bild: Tortenvorschau generieren
  • Bild → Text: Potenziell Kundenbild analysieren
FWas ist ein Guardrail?▾
  • Input Guardrail: Prüft Nutzereingabe (Jailbreak, Spam, toxisch)
  • Output Guardrail: Prüft LLM-Antwort (keine persönlichen Daten, keine falschen Versprechen)
FWas ist Streaming und warum ist es wichtig?▾

Antwort wird Token für Token gestreamt statt auf einmal. Der Nutzer sieht sofort erste Wörter, statt 3-5 Sekunden zu warten. Technisch: Server-Sent Events (SSE).

8 Evaluations & Testing
FWie testet man LLM-Anwendungen?▾
  1. Unit Tests: Einzelne Nodes testen
  2. Integration Tests: Ganzer Graph-Flow
  3. LLM Evaluations: Datensätze mit erwarteten Ergebnissen
FWas ist LLM-as-a-Judge?▾

Ein (stärkeres) LLM bewertet die Outputs eines anderen LLMs:

Frage: "Wie viel kostet eine Schokoladentorte?" Antwort: "Eine Schokoladentorte kostet 45€ in Größe M." Judge: "Bewerte 1-5: Korrektheit, Vollständigkeit, Höflichkeit" Ergebnis: 4/5

Vorteil: Skaliert besser als menschliche Bewertung.
Nachteil: Der Judge kann auch falsch liegen.

9 Architektur-Fragen
FRAG-System für 1 Million Dokumente — wie aufbauen?▾
  1. Chunking: Semantic Chunking (nicht fixed-size)
  2. Vektordatenbank: Pinecone oder Qdrant (skalierbar)
  3. Hybrid Search: Vektor + BM25 Keyword kombiniert
  4. Re-Ranking: Cross-Encoder für Top-50 → Top-5
  5. Caching: Häufige Queries cachen
  6. Metadata Filtering: Vor Vektorsuche filtern
FLLM-Kosten um 80% senken — wie?▾
  1. Kleineres Modell: GPT-4 → GPT-4o-mini (33x günstiger)
  2. Caching: Gleiche Fragen nicht doppelt berechnen
  3. Prompts kürzen: Unnötige Beispiele entfernen
  4. Calls reduzieren: Classify + Extract in einem Call
  5. Kontext beschränken: Nur relevante Nachrichten
  6. Open-Source-Modelle: Llama 3, Mistral für einfache Tasks
FSicherheitsrisiken bei LLM-Anwendungen?▾
  1. Prompt Injection: Nutzer manipuliert Systemverhalten
  2. Data Leakage: Sensible Trainingsdaten preisgegeben
  3. Halluzinationen: Falsche Fakten als wahr dargestellt
  4. Jailbreaking: Sicherheitsregeln umgehen
  5. PII-Exposure: Persönliche Daten in Logs

Gegenmaßnahmen: Guardrails, Input-Sanitization, Output-Filtering, RAG, Log-Anonymisierung.

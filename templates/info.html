Alle Dateien und ihre Verbindungen

main.py → verbindet sich mit ALLEN anderen Dateien

main.py ├── importiert graph.py → startet KI-Durchlauf ├── importiert session_manager → lädt/speichert Gespräche ├── importiert order_db.py → speichert Bestellungen ├── importiert config.py → liest Einstellungen ├── importiert monitoring.py → zählt Metriken ├── importiert cost_optimizer → schätzt Token-Kosten ├── importiert email_service → schickt E-Mails └── importiert pdf_order.py → erstellt PDFs

graph.py → verbindet sich mit nodes.py und state.py

graph.py ├── importiert nodes.py → ruft jeden KI-Schritt auf ├── importiert state.py → kennt das Klemmbrett-Format └── LOGIK: entscheidet welcher Node wann aufgerufen wird

nodes.py → das Herzstück, verbindet sich mit allem

nodes.py ├── importiert config.py → liest Prompts aus YAML ├── importiert state.py → liest/schreibt AgentState ├── importiert error_handler.py → Fehler abfangen ├── nutzt OpenAI API → GPT-4o-mini (Text + Vision) ├── nutzt OpenAI API → gpt-image-1 (Bilder generieren) ├── nutzt HuggingFace API → FLUX/SDXL (Backup-Bilder) └── nutzt ChromaDB → RAG Wissensbasis durchsuchen

state.py → wird von ALLEN anderen gelesen

state.py (das Klemmbrett) ← graph.py liest und schreibt ← nodes.py liest und schreibt ← session_manager.py speichert und lädt ← main.py liest die finale Antwort

config.py → wird von fast ALLEN anderen gelesen

config.py ← liest .env Datei (API-Keys, Passwörter) ← liest prompts_config.yaml (KI-Anweisungen) → gibt alles an nodes.py, main.py, email_service, etc.

Was ist RAG? Wie stark ist es hier?

❌ Ohne RAG 
Kunde: "Was kostet ein Schoko-Kuchen?"
KI: erfindet einen Preis
    → halluziniert ❌
✅ Mit RAG 
Kunde: "Was kostet ein Schoko-Kuchen?"
System: sucht in ChromaDB
→ findet: "Schokolade ab 35€"
KI: antwortet mit echtem Preis ✅

Wie RAG in Kidstorte funktioniert

SCHRITT 1 – Einmalig (ingest.py):
  preise.md + faq.md
       │
       ▼ In kleine Stücke schneiden ("Chunks")
       │
       ▼ OpenAI Embedding → Zahlen-Vektor
  "Schokolade kostet 35€" → [0.23, -0.84, 0.41, ...]
       │
       ▼ ChromaDB speichert: Text + Zahlen

SCHRITT 2 – Bei jeder Preisfrage (nodes.py):
  Kundenfrage: "Was kostet das?"
       │
       ▼ Frage auch zu Zahlen umwandeln
  → [0.22, -0.85, 0.40, ...]
       │
       ▼ ChromaDB vergleicht mit allen Zahlen
  → findet ähnlichsten Chunk (= Preisliste)
       │
       ▼ KI beantwortet mit echtem Inhalt ✅

Wie stark ist das RAG hier?

✅ Stärken
  • Antwortet NUR mit Infos aus deinen Dokumenten
  • Keine erfundenen Preise oder Infos
  • Automatisch aktuell wenn du neu ingest
⚠️ Schwächen
  • Nur bei intent = "price" oder "info" aktiv
  • Bestelldetails kommen NICHT aus RAG
  • Nur .md Dateien unterstützt
Bewertung: Mittelstark – gut für Preise und FAQ, nicht für die eigentliche Bestelllogik

Was ist LangGraph? Ist es wirklich hier drin?

LangGraph ist NICHT installiert. Das Projekt nutzt ein selbst gebautes LangGraph-Muster – es funktioniert genauso, aber ohne die echte Bibliothek.
# Echter LangGraph würde so aussehen:
from langgraph.graph import StateGraph  # ← gibt es hier NICHT

# Kidstorte macht es selbst in graph.py:
class CakeDreamsGraph:
    def run(self, state, user_input):
        state = guardrail(state)
        state = classify_and_extract(state)
        if intent == "order":
            state = extract_info(state)
            state = check_complete(state)
        return state

Vergleich: Echtes LangGraph vs. Kidstorte

FunktionEchtes LangGraphKidstorte
Nodes (Schritte)✅ Ja✅ Ja (nodes.py)
Routing (Weichen)✅ Ja✅ Ja (graph.py)
State (Klemmbrett)✅ Ja✅ Ja (state.py)
Checkpointer (Speicher)✅ Ja✅ Ja (session_manager.py)
Streaming✅ Ja✅ Ja (/api/chat/stream)
Bibliothek installiert✅ Ja❌ Nein (selbst gebaut)
Fazit: Kidstorte ist ein LangGraph-Klon. Gleiche Idee, eigener Code.

Multimodales RAG – Was ist das? Wo ist es?

Monomodal

Versteht NUR Text.
KI liest: "Ich will Elsa-Dekoration" → antwortet

Multimodal ✅

Versteht Text UND Bilder gleichzeitig.
KI sieht dein Referenzfoto + liest Kundenwunsch → erstellt passendes Bild mit Änderungen

3 Schritte in nodes.py

SCHRITT 1: _scan_reference_images + _find_best_reference
  ↓ Lädt alle Bilder aus "Bilder/" Ordner
  ↓ Schickt sie an GPT-4o-mini Vision
  ↓ GPT sieht jedes Bild, vergleicht mit Kundenwunsch
  ↓ Gibt zurück: "Bild 2 passt am besten (Score: 0.85)"

SCHRITT 2: _find_best_reference
  ↓ GPT-4o-mini beschreibt das beste Bild auf Englisch:
  "Fondant figurine of ice queen with platinum blonde braid,
   snowflake decorations, blue and white color scheme..."
  ↓ Diese Beschreibung ist die VORLAGE

SCHRITT 3: generate_single_image
  ↓ gpt-image-1 bekommt: Vorlage + Kundenwünsche
  ↓ Generiert: neues Bild das Vorlage ähnelt aber Wünsche umsetzt

Unterschied: normales RAG vs. multimodales RAG

Normales RAG (Wissen)Multimodales RAG (Bilder)
Was wird gesucht?Textdokumente (.md)Bilder (.jpg, .png)
Wo gespeichert?ChromaDBBilder/ Ordner
Wie wird gesucht?Embedding-ZahlenGPT-4o-mini Vision
Wann aktiviert?Bei Preis/Info-FragenBei Bild-Generierung
ErgebnisText-AntwortGeneriertes Bild

Die Prompt-Stärke – Wie gut ist das Prompt-System?

Wo stecken alle Prompts?

prompts_config.yaml ├── classify_intent → Was will der Kunde? (greeting/order/price/...) ├── extract_info → Welche Details hat er genannt? ├── ask_next → Was soll ich als nächstes fragen? ├── calculate_price → Berechne Preis als HTML-Tabelle ├── answer_question → Beantworte allgemeine Fragen ├── image_description → Beschreibe Kuchen in einem Satz ├── greet → Begrüßungstext └── redirect → Zurück zum Thema führen

Was macht das Prompt-System besonders stark?

1. Hot-Reload – Prompts ändern sich ohne Server-Neustart 
# config.py prüft bei jedem Aufruf ob YAML geändert wurde
mtime = os.path.getmtime(PROMPTS_CONFIG_PATH)
if mtime != _prompts_cache["mtime"]:
    # Neu laden!
2. Kombinierter Classify+Extract Call – spart 50% Kosten 
# nodes.py – Ein einziger API-Call für zwei Aufgaben:
combined_prompt = classify_prompt + extract_prompt
# → gibt zurück: {"intent": "order", "extracted": {"geschmack": "Schoko"}}
3. TODO-Listen-System – fragt nicht dieselbe Frage zweimal 
question_todo = {
  "anlass":    "answered",  # ✅ schon beantwortet
  "gaeste":    "asked",     # ⏳ gefragt, noch keine Antwort
  "geschmack": "pending",   # 🔲 noch nicht gefragt
}
4. Halluzinations-Schutz

STRENGSTE REGEL: Extrahiere NUR was der Kunde WÖRTLICH gesagt hat!
ERFINDE NIEMALS Werte!
Namen BUCHSTABENGENAU übernehmen! (Aron bleibt Aron, nicht Aaron!)

Die KI-Modelle – Welches macht was?

gpt-4o-mini · Text
  • Guardrail-Check (erlaubt/blockiert?)
  • Intent erkennen
  • Bestelldetails extrahieren
  • Nächste Frage stellen
  • Preis berechnen
  • Allgemeine Fragen beantworten
  • Bild-Prompts auf Englisch generieren
gpt-4o-mini · Vision
  • Referenzbilder ansehen
  • Mit Kundenwunsch vergleichen
  • Bestes Bild auswählen + beschreiben
gpt-image-1
  • Kuchen-Vorschaubilder generieren
  • Primärer Bild-Provider
  • Bei normalen Wünschen (ohne echte Namen)
HuggingFace FLUX.1
  • Backup wenn Personennamen (Elsa, Ronaldo…)
  • Wenn gpt-image-1 nicht verfügbar
  • Kein Copyright-Filter
HuggingFace SDXL
  • Backup-Backup-Bildgenerierung
  • Wenn auch FLUX fehlschlägt
text-embedding-3-small
  • Texte in Zahlen umwandeln
  • Für RAG-Suche in ChromaDB

Warum zwei Bild-Provider?

Kundenwunsch: "Elsa Dekoration"
       │
       ▼
_deko_has_person_name("elsa") → TRUE
       │
       ▼
OpenAI würde das BLOCKIEREN
(lässt keine echten Charakternamen zu)
       │
       ▼
Direkt zu HuggingFace FLUX
(kein Copyright-Filter)
       │
       ▼
Prompt: "ice queen princess with platinum blonde braid"
        (OpenAI) ODER "Elsa from Frozen" (HuggingFace)

Der komplette Ablauf einer Bestellung

1. Seite öffnen
main.py gibt Session-Cookie aus → session_id = "abc123"
2. Erste Nachricht
"Hallo, ich möchte einen Kuchen für meinen Sohn"
→ guardrail ✅ → classify → intent="order" → ask_next: "Für wie viele Gäste?"
3. Alle Felder gefüllt
check_complete() → order_complete = True ✅ → summarize_order()
4. Bild generieren
intent = "image" → _find_best_reference() → _build_llm_image_prompt() → gpt-image-1 oder FLUX
5. Bestellung finalisieren
intent = "finalize" → show_address_form = True → Adressformular erscheint
6. Formular abschicken
POST /api/submit-order → order_db.save_order() → PDF erstellen → E-Mail an Kunde + Designer
7. Admin setzt Status "fertig"
order_db.update_order_status(42, "fertig") → Bewertungs-E-Mail wird gesendet
8. Bewertung
Kunde bewertet mit 5 Sternen → order_db.save_rating(42, 5, "Super lecker!")
